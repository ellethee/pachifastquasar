# Messages and locales

## File convention

Messages are TypeScript objects in `locales/<code>.ts`; the code is the file name (`it.ts`, `en.ts`, `pt-BR.ts`),
gathered with `import.meta.glob` and `collectLocales`.

- `it.ts` is the reference language; the others are typed `const en: PachiMessages<typeof it> = {...}`, so a missing
  key is a compile error.
- Each file starts with namespaces (`common`, `errors`, ...). A reusable package uses its own namespace.
- To add a language, add a file. The languages offered to the user are the ones present in the app `messages`.

## Special characters

In vue-i18n messages the characters `@`, `{`, `}` and `|` are special. Write them as literals with the interpolation
syntax: `{'@'}`, `{'{'}`, `{'}'}`, `{'|'}`.

```ts
export default { contact: { mail: 'info{\'@\'}example.com' } }
```

Named parameters use `{name}` and are passed as the second argument of `t` or `pachiT`.

## Messages of a reusable package

A package ships `src/locales/<code>.ts` files, each exporting an object with its own top-level namespace, plus an
index that collects them:

```ts
// src/locales/it.ts
export default { miaLib: { title: 'Titolo' } }

// src/locales/index.ts
import { collectLocales } from '@ilpachi/pachi-i18n'
export const messages = collectLocales(import.meta.glob(['./*.ts', '!./index.ts'], { eager: true, import: 'default' }))
```

```vue
<script setup lang="ts">
import { usePachiI18n } from '@ilpachi/pachi-i18n'
import { messages } from '../locales'

const { t } = usePachiI18n(messages)   // t('miaLib.title')
</script>
```

Rules:

- Messages are registered once per instance, language and namespace.
- Keys the app already defines are never overwritten, so the app can redefine the package texts.
- Only languages already present in the instance are registered: the others, the fallback included, are ignored and
  do not appear in the switcher. A package cannot add languages by itself.
- `usePachiI18n` must be called inside `setup()` (it uses `useI18n`).

## Merging and precedence

`deepMerge(base, override)` merges message trees without mutating the arguments; `override` wins. Use it to combine
sources, passing the least specific first. Example: backend-generated messages first, app overrides last.

```ts
import { deepMerge } from '@ilpachi/pachi-i18n'

const merged = deepMerge(generated.it, overrides.it)
```

When several files share the same language code, `collectLocales` deep-merges them. Messages registered by packages
through `usePachiI18n` have the lowest priority: whatever the app defines for the same key wins.

## Backend error messages

The package does not talk to a backend. In apps built on `@ilpachi/pachifastquasar`, backend error responses
`{ "detail": [{ "loc": [], "msg": "", "type": "", "code": "", "params": {} }] }` are translated by looking up the
`code` under the key `errors.codes.<code>` (with `params` as named parameters). Those messages are generated by the
backend into JSON files per language and combined with the app messages.

```ts
import { pachiT } from '@ilpachi/pachi-i18n'

const text = pachiT(`errors.codes.${detail.code}`, detail.params)
```

The i18n is a global singleton (on `globalThis`) designed for SPAs: SSR is not supported. Package messages are matched to the app languages with `matchLocale` (app `en-US` receives the package `en`), and languages added at runtime are filled the next time `usePachiI18n` runs. Always install the last instance created with `app.use(i18n)`.
